The demo blueprint

Demos exist for every asset that has a website and an application — MEDEXEC, InSnap, CURAVIA, INSNAPP and IEC Docs — and every one follows the same model: a provisioning store as the single source of truth, a one-time activation link (the signer sets their own password — passwords are never emailed), the invited / active / paused / revoked status ladder — preceded by an nda_sent pre-state: invitations from this portal are NDA-first, so a person starts as NDA sent and becomes invited only when the executed NDA triggers provisioning on the asset side — and a login notification to DrMorgan on every activation and sign-in. When a future asset qualifies (website + application) and its demo is built, it plugs into this portal with one registry entry — no new control panel, no separate user list.
